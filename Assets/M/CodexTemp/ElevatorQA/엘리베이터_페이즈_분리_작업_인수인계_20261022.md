# 엘리베이터 안전교육 페이즈 분리 작업 인수인계

작성일: 2026-10-22  
대상: 다음 작업을 이어받을 기획자와 Unity 구현 담당자  
상태: 설계 방향 검토 완료, 페이즈 분리 구현 전

다음 작업의 검토 방향은 엘리베이터 시나리오의 상호작용을 **대화 페이즈, 조사 페이즈, 선택 페이즈**로 나누는 것이다. 각 순간에 필요한 UI와 입력만 활성화해 화면 가림을 줄이고, 플레이어가 지금 해야 할 일을 쉽게 이해하게 한다.

이번 요청은 논의 내용을 인수인계 문서로 저장하는 작업이다. 페이즈 분리 리팩터링은 아직 진행하지 않았으며, 이 문서의 구현 권장안과 미결정 항목을 다음 구현 지시에서 확인한 뒤 적용한다.

## 1 현재 상태와 다음 작업의 목적

현재 엘리베이터 프로토타입은 탑승과 관찰부터 친구의 점프, 고장과 정지, 비상통화 또는 119 모의 신고, 안전한 대기, 구조 완료까지 진행된다. 사건 진행과 선택 기록은 구현되어 있다.

직전 작업에서는 플레이어 눈높이를 친구 눈 위치인 약 Y 1.1064756m로 낮췄다. PC에서는 마우스 이동으로 시점을 회전하고 화면 중앙의 레이저로 조준한 뒤 클릭해 선택한다. Esc로 커서를 풀거나 시점 회전을 다시 켤 수 있다.

UI는 기존 복도 테스트 씬을 참고해 구름 모양의 생각 말풍선, 종이색 카드, 갈색 테두리, 청록 아이콘으로 정리했다. 대사는 위쪽 말풍선에, 선택지는 하단 카드에 표시한다. 생각 말풍선은 시선을 따라오며 관찰 대상에서 시선을 떼면 숨겨진다. 선택 카드는 월드에 고정되어 조준하는 동안 위치가 움직이지 않는다.

다음 작업에서는 이 화면 구성을 바탕으로 페이즈별 표시와 입력을 명확하게 분리한다. 대사, 생각 문구, 행동 선택지가 동시에 활성화되어 집중을 방해하는 상황을 줄이는 것이 목적이다.

## 2 검토한 페이즈 구성

| 페이즈 | 주된 목적 | 표시할 UI | 허용할 상호작용 |
|---|---|---|---|
| 대화 | 친구나 상담원의 이야기를 이해한다 | 대사 말풍선과 필요한 진행 버튼 | 자유로운 시선 이동, 다음 대사 진행 |
| 조사 | 주변의 단서를 살펴본다 | 관찰 테두리, 중앙 레이저, 현재 대상의 생각 문구 | 대상을 가리켜 관찰하고 내용을 확인 |
| 선택 | 관찰과 대화를 바탕으로 행동을 결정한다 | 하단 선택 카드 | 선택지 조준과 실행, 더 살펴보기로 복귀 |

### 대화 페이즈

친구, 상담원, 구조대원의 발화에 집중할 수 있도록 대사와 진행에 필요한 버튼만 표시한다. 조사용 생각 말풍선과 행동 선택 카드는 숨기는 방향이다.

시선은 자유롭게 움직일 수 있어야 한다. 대화를 듣기 위해 카메라를 특정 방향으로 강제 회전시키지 않는다. 짧게 이어지는 대사를 적절히 묶어, 한 문장마다 다음 버튼을 누르는 부담을 줄인다.

### 조사 페이즈

같은 청록색 테두리를 관찰 가능 표시로 사용한다. 친구, 문, 층 표시기, 비상통화 장치, 안전 안내문, 위치와 식별 안내에 같은 규칙을 적용한다.

대상을 가리키면 현재 상황에 맞는 생각 문구를 표시하고, 시선을 떼면 숨긴다. 행동 선택 카드는 숨겨 조사에 집중할 수 있게 한다. 모든 대상을 확인해야 진행되는 조건이나 조사 시간 제한은 두지 않는다.

조사를 마치고 다음 페이즈로 넘어가는 경로는 작은 진행 버튼이나 친구와 이야기하기처럼 명시적인 조작으로 제공하는 것을 권장한다.

### 선택 페이즈

조사 생각 말풍선을 정리하고 하단 선택 카드에 집중하게 한다. 선택지를 읽는 동안 배경 대상을 가리킨 것만으로 조사 말풍선이 다시 나타나지 않게 한다.

선택 카드의 기본색은 동일하게 유지한다. 정답과 위험 행동을 색으로 미리 구별하지 않는다. 주변을 다시 확인하고 싶을 때는 더 살펴보기로 조사 페이즈에 돌아갈 수 있어야 한다.

## 3 엘리베이터 시나리오에 적용할 흐름

### 친구의 점프 제안

1. 친구와 함께 탑승한 상태에서 주변을 조사한다.
2. 친구의 “여기서 한 번 뛰어볼까?” 대화를 듣는다.
3. 선택 페이즈에서 다음 세 가지 중 하나를 고른다.
   - “위험해. 뛰지 말자.”
   - “조금만 뛰어보자.”
   - “주변을 더 살펴본다.”
4. 더 살펴보기를 고르면 조사로 복귀한다. 이 선택으로 점프를 시작하지 않는다.
5. 말리기나 동조를 고르면 해당 판단을 기록하고 친구의 반응 대화를 보여준다.
6. 친구가 뛰고 착지한 직후 엘리베이터가 고장 나서 멈춘다.

말렸던 경우에도 친구는 만류를 무시하고 뛴다. 친구를 말린 판단은 올바른 판단으로 인정하며, 친구가 말을 듣지 않은 일을 플레이어의 실패로 처리하지 않는다. 동조했던 경우에도 같은 고장 사건으로 이어지고, 정답을 고를 때까지 초기 선택을 반복시키지 않는다.

### 고장 후 도움 요청

1. 친구가 당황한 대화를 하고 초기 판단에 따른 피드백을 받는다.
2. 조사 페이즈에서 비상통화 장치, 문, 안전 안내, 건물명과 승강기 식별 정보를 확인한다.
3. 선택 페이즈에서 대처 방법을 결정한다.
4. 비상통화 장치를 작동하면 연결 상태를 거쳐 상담원과 대화한다.
5. 위치와 갇힌 상황을 전달하고 안내를 확인한다.
6. 도움 요청이 전달된 뒤 친구를 안심시키고 안전하게 기다린다.
7. 구조대원의 안내 후 결과 화면으로 넘어간다.

통화 과정에는 대화와 선택이 여러 번 필요할 수 있다. 하나의 통화 사건 안에서 상담원의 안내를 듣고, 응답을 고르고, 다음 안내를 듣는 식으로 페이즈를 전환한다. 위치를 다시 확인할 필요가 있을 때 조사로 돌아가는 경로도 검토한다.

### 위험 행동과 비상통화 무응답

- 위험 행동은 실행 직전에 Wait로 중단하고 이유를 설명한 뒤 해당 대처 선택으로 돌아간다. 재도전 후에도 첫 시도 기록을 보존한다.
- 비상통화에 응답이 없으면 휴대폰으로 119에 모의 신고하고, 위치와 갇힌 상황을 전달한 뒤 구조 대기로 합류한다.
- 도움 요청 전 아무 행동 없이 기다리는 상태와, 요청 후 안내를 따라 기다리는 상태를 구분한다.
- 도움 요청과 위치 전달 없이 구조 완료로 넘어가지 않도록 기존 조건을 유지한다.

## 4 구현 구조 권장안

### 사건 단계와 상호작용 페이즈를 함께 관리

사건의 진행과 플레이어의 현재 상호작용 방식을 별도로 표현하는 구조를 권장한다. 예를 들어 엘리베이터가 고장 나서 멈춘 사건 단계 안에서도 대화, 조사, 선택이 차례로 필요하다.

현재 상태는 다음과 같다.

- 기존 사건과 진행 상태: `ElevatorStep`
- 현재 값: `Observe`, `Proposal`, `Jump`, `Stopped`, `Connecting`, `Call`, `Unanswered`, `Waiting`, `Retry`, `Rescue`, `Complete`
- 추가 검토 대상: `InteractionPhase`와 `Dialogue`, `Investigation`, `Choice`

위 새 이름은 구현 제안이다. 현재 코드에 추가되어 있지는 않다. 기존 `ElevatorStep`에는 사건과 조작 성격이 함께 들어 있으므로, 각 값을 새 페이즈에 단순히 일대일 대응시키기 전에 전환 책임을 정리한다.

페이즈를 바꾸는 것만으로 점프, 신고, 구조 완료 같은 사건 효과가 실행되지 않게 한다. 사건 효과는 해당 행동이 확정되었을 때 한 번만 실행한다.

### 페이즈별 표시와 입력 조건

페이즈 전환을 한 경로에서 처리하고, 해당 페이즈의 UI 표시와 입력 허용 조건을 함께 갱신한다.

- 대화로 들어가면 조사 생각과 행동 카드를 정리하고 대사를 표시한다.
- 조사로 들어가면 이전 대사와 선택 UI를 정리하고 관찰 입력을 허용한다.
- 선택으로 들어가면 조사 강조와 생각 문구를 정리하고 선택 입력을 허용한다.
- 점프, 연결 대기, 구조 연출에서는 기존 사건 상태에 맞춰 전환 입력을 잠시 제한한다.
- 재시작과 개발용 단계 이동은 사건 상태, 페이즈, 말풍선, 선택 UI, 조준 대상, 타이머와 입력 잠금을 함께 초기화한다.

PC와 XR이 같은 페이즈 허용 조건을 거치게 한다. 입력이 비활성인 페이즈에서도 시선 이동은 유지한다. 중앙 레이저는 진행 버튼과 선택 카드를 조준할 때도 사용할 수 있어야 한다.

친구의 반응을 별도 대화 페이즈로 옮길 때는 기존 점프 상태의 `friendReplySeconds`와 대사 표시가 중복되지 않도록 확인한다.

### 우선 확인할 파일

| 파일 | 다음 작업에서 확인할 책임 |
|---|---|

| `Assets/M/Scripts/Elevator/ElevatorLesson.cs` | 관찰과 행동 실행 분리, 대사와 연출 연결, 재시작 처리 |
| `Assets/M/Scripts/Elevator/ElevatorView.cs` | 페이즈별 UI 표시와 숨김, 말풍선과 선택 카드의 중복 표시 방지 |
| `Assets/M/Scripts/Elevator/ElevatorObservation.cs` | 조사 페이즈에서만 관찰과 강조를 활성화하는 조건 |

## 5 구현 전에 확정할 UX 항목

아래 내용은 구현 권장안이며 아직 세부 동작이 확정되지 않았다.

| 항목 | 권장 기본안 | 확인할 점 |
|---|---|---|
| 조사 종료 | 작은 진행 버튼으로 명시적으로 종료 | 모든 대상 확인을 강제하지 않으면서 다음 행동을 쉽게 찾는가 |
| 대화 진행 | 짧은 대사를 묶고 필요한 곳에 다음 버튼 제공 | 자동 진행 여부와 읽기 시간, 다시 듣기나 건너뛰기 제공 범위 |
| 조사 중 장치 클릭 | 장치를 확인하거나 관련 행동 선택을 여는 데 사용 | 클릭만으로 신고가 즉시 실행되는지, 선택 페이즈를 거치는지 |
| 최초 제안 진입 | 친구와 이야기하기를 명확한 진입 경로로 유지 | 기존 제안 지연 타이머가 조사 도중 대화를 자동으로 시작해도 되는가 |
| 선택 중 추가 조사 | 더 살펴보기 후 같은 질문으로 복귀 | 조사 복귀 때문에 선택 기록이나 사건이 중복 실행되지 않는가 |

조사 중 행동 선택을 여는 방식과 즉시 행동을 실행하는 방식은 구분해야 한다. 현재 구현은 친구 클릭으로 제안을 열고, 정지 후 비상통화 장치 클릭으로 연결을 시작한다. 페이즈 분리 시 이 동작의 처리 방식을 먼저 정한다.

## 6 다음 작업의 완료 기준

- 대화 중에는 조사 생각과 행동 선택 카드가 끼어들지 않는다.
- 조사 중에는 행동 선택 카드가 숨겨지고, 같은 규칙의 관찰 테두리와 생각 문구가 동작한다.
- 선택 중에는 배경을 조준해도 조사 말풍선이 다시 나타나지 않는다.
- 더 살펴보기로 조사에 돌아갔다가 동일한 질문의 선택을 다시 열 수 있다.
- 말리기와 동조 모두 친구의 점프와 착지 후 고장으로 이어지며 예방 판단 기록은 다르게 남는다.
- 비상통화 성공, 무응답 후 119 모의 신고, 위험 행동 중단과 재도전 경로가 유지된다.
- 도움 요청 없이 대기하는 상태에서는 힌트만 제공되고 구조 완료로 진행되지 않는다.
- 중복 클릭, 다음 버튼 연타, 페이즈 전환 직후 남은 클릭으로 사건이 두 번 실행되거나 다음 선택이 자동 실행되지 않는다.
- 재시작과 개발용 단계 이동 후 이전 페이즈의 UI, 테두리, 조준 상태, 소리와 타이머가 남지 않는다.
- 친구 눈높이의 시점, 마우스 시점 회전, 중앙 선택 레이저와 Esc 커서 전환이 유지된다.
- 선택 카드는 조준 중 월드에 고정되고, 조사 생각은 시선을 따라 읽을 수 있다.
- 대화, 조사, 선택 화면을 각각 캡처해 친구와 주요 장치를 가리는 면적과 한글 가독성을 확인한다.
- PC 검증과 VR 실기기 검증 결과를 구분해서 보고한다.

## 7 실행 위치와 작업 경계

실행 씬은 `Assets/M/Scene/Elevator_Safety_Prototype.unity`이다. 현재 사용 안내는 `Assets/M/Scene/README_엘리베이터.txt`에 있다.

이 대화에서 Unity 구현과 검증을 진행한 작업 공간은 `D:\project\ProjectWait`이다. 이 인수인계 문서의 저장 위치는 `E:\ProjectWait\Document`이며, 해당 E 드라이브 폴더에는 실행 씬이 없다. 다음 작업 시작 시 연결된 Unity 에디터의 실제 프로젝트 경로를 확인한다.

Unity 구현 파일과 산출물은 기존 지침에 따라 `Assets/M/` 내부에서 작업한다. 원본 복도 테스트 씬, 공용 코드, `Packages/`와 `ProjectSettings/`는 읽기 전용 참고로 유지한다. 이번 문서 저장 요청은 문서 목적지에 대한 예외이며 Unity 자산의 수정 범위를 넓히는 요청은 아니다.

친구 공유 모델은 `Assets/Shared Assets/Models/Friend/`에 저장되어 있다. 이번 페이즈 분리 작업을 위해 모델을 다시 만들거나 이동할 필요는 없다.
